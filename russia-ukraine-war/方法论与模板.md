## 一、研究阶段：把选题拆成维度再并行搜

不要一上来就搜"XX 战争全貌"这种大而空的关键词。先把选题拆成**彼此独立、互证互补**的维度，每个维度单独搜一轮，再交叉比对。

### 1.1 通用维度拆分表（以冲突类为例）

| 维度 | 搜索意图 | freshness 建议 |
|---|---|---|
| 当前态势 | 最新战场/行业动态 | `m3`（近 3 月）|
| 历史脉络 | 时间线、关键节点 | `y1`（近 1 年或不过滤）|
| 伤亡/规模 | 量化数字、双方口径 | `m3` |
| 经济/代价 | 制裁、GDP、重建成本 | `m3` |
| 纵深博弈 | 能源战、技术战、制裁外溢 | `m1`（更实时）|
| 外交 | 谈判、方案条款、各方立场 | `m3` |
| 国际格局 | 盟友、第三方、全球南方 | `m2` |

> 技巧：每个维度用**中英文各一组合关键词**并行搜索（中文源覆盖官方/媒体口径，英文源覆盖 ISW/CSIS/IEA 等机构）。一轮 `WebSearch` 调用里可放多条独立 query。

### 1.2 来源优先级与交叉验证

- **首选一手/机构源**：ISW（战争研究所）、CSIS、IEA、世界银行 RDNA、联合国、Mediazona×BBC（实名核实阵亡）。
- **二手媒体源**用于补充细节与现场叙述，务必**多源比对同一数字**。
- **口径差异必须保留并标注**：如伤亡数，CSIS 估俄 120–140 万、中文媒体引"约 180 万"，页面中要说明统计时点与范围差异，绝不强行统一。
- **存疑即标注**：凡"媒体报道版本""据消息人士"，一律加"媒体报道版本""据称"等限定词。

## 二、结构建模：把资料映射成网页骨架

研究完一轮后，把零散信息收敛为**固定章节结构**。冲突/复盘类通用 9 章：

```
01 总览 Overview        —— 一眼看懂的 4 个关键指标卡
02 脉络 Timeline        —— 时间线（分阶段的节点）
03 核心态势 Frontline    —— 当前主要矛盾与对比
04 量化维度 A            —— 数据表格 + 条形图
05 量化维度 B            —— 数据表格 + 条形图
06 代价/经济 Economy     —— 双栏对比（双方）
07 外交 Diplomacy        —— 约束条件 + 方案条款表
08 格局 World            —— 多方力量对比
09 研判 Outlook          —— 情景卡 + 观察点清单
```

**可视化清单**（按出现频率从高到低）：
1. 顶部 statbar（4 个核心数字）
2. 数据表格（多源口径对照）
3. 纯 CSS 条形图（推进速度、占比、规模，相对量级）
4. 垂直时间线（左右分栏：年份 + 事件）
5. 双栏对比卡（A 方 vs B 方）
6. 情景卡（带概率权重）
7. 引用块（标注来源，带 `ru`/`ua` 配色变体）

## 三、网页生成：单文件、零依赖、暗色仪表盘

### 3.1 设计语言（固定一套，省去每次返工）

- **配色**：深底 `#0b0f14` + 面板 `#151d27`；双方用固定语义色（例：俄红 `#e8574a` / 乌蓝 `#4a9eff` / 警示金 `#e8b04a`）。
- **字体**：正文系统无衬线；数字/标签用等宽 `monospace`，强化"数据感"。
- **密度**：卡片化、紧凑面板；正文克制，数字与表格当主角。

### 3.2 关键组件（已验证可复用）

- **吸顶导航 + 滚动高亮**：scroll 计算当前 section，给 nav `<a>` 加 `.on` 类。
- **纯 CSS 条形图**：`.track` + `.fill`（`.ru`/`.ua` 渐变），进入视口时用 `IntersectionObserver` 从 `width:0` 动画到目标宽度。
- **时间线**：左侧渐变竖线 `::before`，每个事件用 `.bd::before` 圆点（按 hot/win 切换配色）。注意**年份标签宽度**——窄列会被竖线裁切，本例最终用 `grid-template-columns:96px 1fr` 才不截断。
- **入场动画**：对 `.grid/.tl/table/.card/blockquote` 批量加 `.reveal`（opacity+translateY），`IntersectionObserver` 阈值 0.12 触发。
- **响应式**：`@media(max-width:640px)` 缩进导航、时间线年份列、栅格列数。

### 3.3 铁律

- **单文件、内联 CSS/JS**，不引外部 CDN（沙箱/离线都能开）。
- **所有数字配来源**，表格末行或脚注注明出处与口径。
- **不要伪造图片**：无真实图就不放 `<img>`，用文字/图表替代（本例全程纯 CSS，零图片）。

## 四、校验：先查标签，再肉眼看渲染

### 4.1 标签闭合检查（Python，秒级）

```python
import re
h = open('page.html', encoding='utf-8').read()
for t in ['section','table','div','blockquote','ul','p','h3']:
    o = len(re.findall(r'<%s[ >]' % t, h))
    c = len(re.findall(r'</%s>' % t, h))
    print(f'{t:10s} {o} 开 / {c} 闭', 'OK' if o == c else '✗ 不匹配')
```

> 实战踩坑：本例曾出现 `<div class="h2sub">...</h2>` 这种开闭标签错配（复制粘贴时把 `</div>` 误写成 `</h2>`），导致 div 深度整体偏移 2。写完即用上面的脚本扫一遍，比肉眼找快得多。

### 4.2 渲染校验（Playwright + 本地 Chromium）

沙箱内已备可用 Chromium（路径 `/root/.cache/ms-playwright/chromium-1208/chrome-linux64/chrome`）。流程：

```bash
# 1) 起本地静态服务器
cd /workspace && python3 -m http.server 8899 &

# 2) 用 playwright 逐 section 截图（指定 executablePath，加 --no-sandbox）
node shot.js   # 脚本遍历 9 个 section 各截一张，再逐张 Read 肉眼看
```

- 截图后**逐张 Read 查看**：重点查时间线年份是否截断、表格是否溢出、条形图动画、移动端断点。
- 发现样式问题 → 改 CSS → 重新截图，形成闭环。

最终用 `present_files` 给出 `/workspace` 下的成品（HTML 会自带浏览器预览），并口头说明核心结论与数据口径。
